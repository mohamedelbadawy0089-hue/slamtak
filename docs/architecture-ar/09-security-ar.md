## 1. نموذج الثقة

| الحد | داخل الحد (موثوق) | خارج الحد (غير موثوق) |
|---|---|---|
| المتصفح | لا شيء | كل شيء: مدخلات، توكنات في JS، الطلبات |
| Edge/Gateway | بعد التحقق | قبل التحقق |
| API + قاعدة البيانات | موثوق بالكود والقيود | — |
| الخدمات الخارجية | لا شيء (تُعامل كغير موثوقة، تُتحقق استجاباتها) | — |

**Zero Trust عمليًا:** كل طلب يُصادَق ويُصرَّح له من جديد؛ لا «جلسة موثوقة» تتجاوز الفحص؛ لا شبكة داخلية موثوقة؛ لا اعتماد على إخفاء الواجهة.

## 2. المصادقة (Authentication)

| البند | القرار |
|---|---|
| كلمة المرور | Argon2id: `m=19456 KiB, t=2, p=1, salt=16B` — تُخزَّن في PHC string |
| سياسة الكلمة | ≥ 12 حرفًا، فحص ضد قائمة كلمات مسرّبة (k-anonymity اختياري)، لا انتهاء صلاحية قسري |
| MFA | TOTP إلزامي للمالك/المدير، اختياري للموظف؛ + 8 أكواد احتياطية مُشفّرة |
| الجلسة | Access JWT ES256 (15 دقيقة) + Refresh (7 أيام، **تدوير مع كشف إعادة الاستخدام**) |
| التخزين | كوكي `__Host-session`: `HttpOnly; Secure; SameSite=Lax; Path=/` — لا توكن في JS |
| تحقق إضافي | ربط الجهاز (بصمة UA+IP مقنّعة) → إشعار عند جهاز جديد |
| قفل الحساب | 5 محاولات فاشلة → قفل متزايد المدة يبدأ بـ15 دقيقة؛ تصعيد إلى المالك |
| إعادة تعيين | رمز أحادي صالح 30 دقيقة، يُبطل كل الجلسات، ولا يكشف وجود البريد |
| الخروج | إبطال الجلسة خادميًا + حذف الكوكي |

**حدود معروفة:** لا SMS مجانًا؛ لذلك TOTP + بريد كقناة ثانية، وSMS عبر Adapter عند الدفع.

## 3. التصريح (Authorization)

- كل مسار يعلن `permission code` (انظر `08`).
- الصلاحيات تُحسب في الخادم من `user_roles → role_permissions`، لا من التوكن وحده عند العمليات الحساسة (تحقق مزدوج من القاعدة للعمليات `is_sensitive`).
- **RLS** طبقة مستقلة إجبارية (`FORCE`).
- **فصل المهام** بقيد قاعدة (المُنشئ ≠ المعتمد).
- **Step-up** للعمليات الست الحساسة.

## 4. حماية الويب (Web Security)

| التهديد | الضابط |
|---|---|
| **SQL Injection** | استعلامات معاملية فقط (Drizzle/`pg` prepared)؛ `raw` ممنوع بلا مراجعة؛ لا دمج نصي في SQL |
| **XSS** | React escaping افتراضيًا، لا `dangerouslySetInnerHTML` بلا تعقيم (DOMPurify)؛ **CSP صارم** أدناه؛ الكوكي `HttpOnly` يحدّ الأثر |
| **CSRF** | `SameSite=Lax` + فحص `Origin`/`Referer` على كل طلب متغيّر + Double-submit token (`X-CSRF-Token`) |
| **Clickjacking** | `frame-ancestors 'none'` + `X-Frame-Options: DENY` |
| **MIME sniffing** | `X-Content-Type-Options: nosniff` |
| **التسريب عبر المُحيل** | `Referrer-Policy: strict-origin-when-cross-origin` |
| **فتح نوافذ** | `rel="noopener noreferrer"` |
| **HSTS** | `max-age=63072000; includeSubDomains; preload` |
| **Service Worker** | نطاق محدود، لا تخزين استجابات API خاصة، إصدار وتوقيع |
| **الملفات** | فحص نوع/حجم، تخزين خارج الجذر، أسماء لا تُخمَّن، روابط موقّعة 15 دقيقة، `Content-Disposition: attachment` |
| **Open Redirect** | قائمة مسارات داخلية مسموحة بعد تسجيل الدخول |

**CSP المعتمد:**
```text
default-src 'self';
script-src 'self' 'nonce-<random>' 'strict-dynamic';
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:;
connect-src 'self' <realtime-endpoint>;
font-src 'self';
object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none';
upgrade-insecure-requests;
```

## 5. حدود المعدل (Rate Limiting)

| المسار | الحد | المفتاح | الاستجابة |
|---|---|---|---|
| `POST /auth/login` | 5 / 15 دقيقة | `ip + identifier` | 429 + تأخير تصاعدي |
| `POST /auth/forgot` | 3 / ساعة | `ip + identifier` | 429 (رسالة محايدة) |
| `POST /auth/mfa/verify` | 6 / 10 دقائق | `session` | 429 + قفل |
| API عام (مصادق) | 120 / دقيقة | `user_id` | 429 + `Retry-After` |
| الكتابة (`POST/PUT/PATCH`) | 60 / دقيقة | `user_id` | 429 |
| التصدير | 5 / ساعة | `tenant_id` | 429 + طابور |
| المسح/البحث | 300 / دقيقة | `tenant_id` | 429 |
| Webhook/مهمة | 60 / دقيقة | `tenant_id` | 429 |

التنفيذ: Cloudflare + جدول `rate_limits` داخل القاعدة (نافذة منزلقة) — لا Redis في الملف A.

## 6. الأسرار والتشفير

| البند | القرار |
|---|---|
| المتغيرات | `env` فقط؛ لا أسرار في Git، لا في كود، لا في سجلات |
| التخزين | مدير أسرار المنصة (Sites/Cloudflare secrets أو Supabase secrets) |
| الدوران | مفاتيح JWT كل 90 يومًا (`kid` متعدد، إبطال تدريجي)؛ مفاتيح API الخارجية كل 180 يومًا. أما مفتاحا Supabase القديمان `anon`/`service_role` فلا يُدوَّران، بل يُستبدلان بـ`publishable`/`secret` ثم يُعطَّلان — أسفل الجدول |
| النقل | TLS 1.3، لا HTTP، `upgrade-insecure-requests` |
| السكون | تشفير القرص/النسخ عند المزود + تشفير الحقول الحساسة (الرقم القومي، أكواد TOTP، بيانات الرواتب) بـ AES-256-GCM في الخدمة |
| التجزئة | كلمات المرور Argon2id؛ الرموز (invite/reset) SHA-256؛ لا تشفير قابل للعكس لكلمات المرور |
| السجلات | تنقية تلقائية للحقول الحساسة (password, token, authorization, national_id) قبل الكتابة |
| `.dev.vars` | مستثنى في `.gitignore` وغير متتبَّع؛ لا يُدفع ولا يُشارَك، والنسخة المحلية تُحذف بعد إبطال ما فيها |

**مفتاح Supabase قديم مسرّب (`anon`/`service_role`):** التدوير لم يبقَ متاحًا لهذين المفتاحين، والمسار الصحيح هو الاستبدال ثم التعطيل، وبهذا الترتيب:

1. Settings → **API Keys** → تبويب *Publishable and secret API keys* → **Create new API keys**؛ `sb_publishable_…` يعوّض `anon` في المتصفح، و`sb_secret_…` يعوّض `service_role` في الخادم فقط ولا يدخل المتصفح ولا المستودع.
2. استبدل `anon` بـ`sb_publishable_…` في `public/supabase-config.js` وفي السرّ `SUPABASE_ANON_KEY` في GitHub Actions وفي أي متغيّر بيئة استضافة، ثم أعد النشر.
3. تحقّق: `npm run check:supabase` لا يعيد `2`، ودخول حقيقي من المتصفح ناجح.
4. **بعد** التحقق فقط: Settings → API Keys → المفاتيح القديمة → **Disable**. تعطيل `service_role` القديم يُبطل `anon` القديم معه، ولهذا تتقدّم الخطوة 2.
5. أعد `npm run check:supabase` وتأكّد أنه `0`، ثم احذف المفتاح القديم من أي نسخة محلية.
6. حذف المفتاح من تاريخ Git لا يُغني عن الخطوة 4؛ المفتاح المسرّب يبقى صالحًا ما دام ممكّنًا في المشروع.

التفصيل عند المزوّد: [rotate leaked API keys](https://supabase.com/docs/guides/security/rotate-leaked-api-keys) و[migrating to new API keys](https://supabase.com/docs/guides/getting-started/migrating-to-new-api-keys).

## 7. التسجيل الأمني والمراقبة

| الحدث | المستوى | التنبيه |
|---|---|---|
| دخول ناجح من جهاز جديد | info | بريد للمستخدم |
| فشل دخول متكرر | warn | تصعيد عند 5 |
| `TENANT_MISMATCH` | **critical** | فوري (بريد + Sentry) |
| محاولة صلاحية مرفوضة على عملية حساسة | warn | تقرير يومي |
| تغيير صلاحية/دور | info | بريد للمالك |
| تغيير إعداد أمني | warn | بريد للمالك |
| دخول دعم للمنصة | critical | بريد للعميل + سجل كامل |
| تعديل/حذف محاولة على `audit_logs` | critical | تنبيه + فشل العملية |
| نسخ احتياطي فاشل | critical | فوري |

**الاحتفاظ:** سجلات أمنية 12 شهرًا على الساخن، `audit_logs` 5 سنوات.

## 8. نموذج التهديد (STRIDE — مختصر عملي)

| التهديد | السيناريو الواقعي | الضوابط |
|---|---|---|
| **Spoofing** | سرقة كوكي/جلسة | HttpOnly + SameSite + تدوير Refresh + كشف إعادة الاستخدام + ربط الجهاز |
| **Tampering** | تعديل سعر/كمية في الطلب | تحقق Zod + حساب السعر خادميًا + تدقيق قبل/بعد + Idempotency |
| **Repudiation** | «لم أُلغِ الفاتورة» | `audit_logs` append-only + توقيع الفاعل والوقت وIP |
| **Information Disclosure** | قراءة منتجات/أسعار مخزن آخر | RLS + FK مركبة + 404 + اختبارات A1–A12 |
| **Denial of Service** | إغراق البحث/التصدير | Rate limit + تصدير في طابور + `statement_timeout` |
| **Elevation of Privilege** | موظف يمنح نفسه `finance.*` | `grant ⊆ own` + Step-up + `token_version` + تدقيق |
| **Insider (داخلي)** | أمين مخزن يُسقط كميات | SoD + اعتماد + مطابقة دورية + تقرير انحراف |
| **Supply chain** | حزمة npm خبيثة | lockfile + `pnpm audit` + Dependabot + ممنوع `postinstall` غير مراجَع |
| **Backup theft** | تسريب نسخة | نسخ مشفّرة + وصول محدود + مفاتيح منفصلة |
| **Data loss** | حذف جدول بالخطأ | لا `DELETE` لدور التطبيق على التاريخ + نسخ + PITR (خطة مدفوعة) |

**مخاطر مقبولة صراحة:** لا اختبار اختراق خارجي قبل الإطلاق التجاري (D-3)؛ RPO = 24 ساعة في الخطة المجانية؛ لا WAF متقدم مدفوع.

## 9. حماية سلسلة التوريد و CI

- تثبيت إصدارات دقيقة + lockfile (بلا `^`).
- بوابة الأسرار الفعلية الآن: `npm run check:secrets` في سير `secret-guard`، تفشل عند وجود `.dev.vars` أو `.env` متتبَّع أو اختفاء قاعدة تجاهله. أما `gitleaks` (يفحص سجل Git كاملًا لا الأسماء فقط) و`Trivy` و`pnpm audit` (والمستودع يستخدم npm: `npm audit`) فليست في CI بعد، وإضافتها في Phase 1.
- مراجعة بشرية لأي ترقية Major، ولا تُرقّى تلقائيًا.
- توقيع commits (اختياري) وحماية فرع `main` (مراجعة إلزامية + فحوص خضراء).
- لا أسرار في CI logs؛ استخدام OIDC/Secrets.

## 10. الاستجابة للحوادث (Incident Response)

| المرحلة | الإجراء | المسؤول | الزمن المستهدف |
|---|---|---|---|
| اكتشاف | تنبيه Sentry/Uptime/تنبيه أمني | المناوب | ≤ 15 دقيقة |
| احتواء | إبطال الجلسات، تعطيل الحساب/المفتاح (وليس تدويره إن كان من نوع لا يُدوَّر: §6 أعلاه)، عزل الميزة | Backend | ≤ 1 ساعة |
| تقييم | ما البيانات المتأثرة؟ أي مستأجرين؟ | أمن + معماري | ≤ 4 ساعات |
| إصلاح | تصحيح + اختبار انحدار + نشر | Backend | حسب الخطورة |
| إبلاغ | إشعار المتأثرين إن لزم (قانوني) | المالك | ≤ 72 ساعة |
| تعلّم | Post-mortem بلا لوم + بند في الاختبارات | الكل | ≤ 5 أيام |

**Runbooks مطلوبة قبل الإطلاق:** تسريب جلسة، فشل نسخ احتياطي، انحراف أرصدة، تعطّل قاعدة، ارتفاع أخطاء 500، محاولة تسريب مستأجر.
