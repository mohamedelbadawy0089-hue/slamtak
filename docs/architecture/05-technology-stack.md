# 05 — Technology Stack Document

> **تحديث قيد التكلفة الصفرية (2026-11-06):** ما يظهر لاحقًا من Redis/BullMQ أو VPS أو تكلفة شهرية مُستبدَل بما في [`27`](27-free-tier-architecture.md) §5. المرجع الحاكم هو `27`.

> **سياسة الإصدارات:** نُثبّت إصدارات دقيقة في `package.json` و`pnpm-lock.yaml` (بلا `^`)، ونستخدم `renovate` أسبوعيًا بمراجعة يدوية. الأرقام أدناه **الخط الأساسي المعتمد**؛ يُرفع بعد اختبار في `staging` لا تلقائيًا.

## 6. حل تعارضات التقنيات (Conflict Resolution)

هذا القسم إلزامي: كل تعارض ظاهري في المتطلبات حُلَّ قبل اعتماد التصميم.

### C1 — Supabase (BaaS) × بوابة الـAPI ⚠️ تعارض جوهري
- **التعارض:** Supabase يوفّر PostgREST + Auth + Storage مباشرة للمتصفح؛ والبوابة تفترض أنها المنفذ الوحيد. استخدام الاثنين = مصدرا حقيقة وسطحا هجوم.
- **الحل:** Supabase يُستخدم **كقاعدة PostgreSQL مُدارة فقط** (وStorage اختياريًا). `REVOKE` على `anon`/`authenticated` في مخطط `public`، وPostgREST وAuth **بلا استخدام**. كل الوصول عبر Edge Functions.
- **الأثر:** يبقى الاستفادة من النسخ الاحتياطي والإدارة بلا التضحية بحد الثقة.

### C2 — RLS × Connection Pooler × ORM
- **التعارض:** RLS يعتمد على متغير جلسة (`app.tenant_id`)، والتجميع في وضع المعاملة يعيد استخدام الاتصالات.
- **الحل:** `set_config('app.tenant_id', …, true)` أي **`SET LOCAL` داخل معاملة** فقط؛ ممنوع `SET` الدائم؛ ممنوع `pg_advisory_lock` غير `_xact_`؛ Drizzle يدعم ذلك صريحًا.
- **الفحص:** اختبار تكامل يفتح 50 معاملة متوازية بمخزنين مختلفين ويتأكد من عدم التسريب.

### C3 — Supabase Auth × المصادقة الذاتية (لا ترحيل كلمات مرور)
- **التعارض:** كلمات مرور GoTrue غير قابلة للتصدير (تجزئة داخلية).
- **القرار (ADR-026):** لا ترحيل مستخدمين. كل حساب يُنشأ من جديد بكلمة مرور Argon2id خاصة به وMFA؛ فلا حاجة لمسار تحقق مزدوج ولا لإبقاء GoTrue مفتوحًا.
- **التالي:** GoTrue يُغلق من اليوم الأول (`REVOKE` على PostgREST وAuth بلا استخدام)، ما يزيل سطح هجوم كاملًا.

### C4 — Next.js API Routes × Edge Functions
- **التعارض:** Next.js يستطيع تنفيذ منطق على الخادم، فيصير لدينا مصدرا منطق.
- **الحل:** Next.js على Pages يُبنى ثابتًا؛ `route handlers` لا تُستخدم لمنطق أعمال، وأي منطق = Edge Functions. لا وصول للقاعدة من الواجهة.

### C5 — Tailwind 4 × shadcn/ui
- **التعارض:** إصدارات المكونات قد تتأخر عن Tailwind 4.
- **الحل:** Phase 1 تبدأ بـ Spike يومين؛ إن ظهر تعارض غير قابل للحل نُثبّت Tailwind 3.4 (توافق مضمون) ونؤجل الترقية. القرار يُسجَّل في ADR-016.

### C6 — WebSocket × SSE × Edge Functions
- **التعارض:** Edge Functions لا تفتح WebSocket، وSSE بدفق يعيد الاتصال كل 120 ثانية فيُحسب استدعاءً جديدًا ويؤخر الإشعار 3 ثوان.
- **الحل (ADR-024):** **Supabase Realtime** بقنوات خاصة للتحديث الفوري (<300ms) بحمولة حدث بلا بيانات؛ و**SSE احتياطي** عند حجب WebSocket. الواجهة تستخدم طبقة `RealtimeClient` واحدة تخفي الفرق، وكلاهما يستدعي `/api` لجلب الحقيقة.

### C7 — الواجهة الحالية (SPA ثابت) × Next.js
- **الحل:** الواجهة الحالية تبقى تعمل خلف مسار `/legacy` أثناء الانتقال، وتُزال وحدةً بوحدة (Strangler)؛ لا إعادة كتابة شاملة.

### C8 — أصل واحد × نطاق API منفصل
- **التعارض:** `api.example.com` مع كوكيز = مشاكل SameSite/CORS/CSRF.
- **الحل:** أصل عام واحد `app.example.com`، و`/api/*` يُوجَّه داخليًا. الكوكيز `HttpOnly; Secure; SameSite=Lax; Path=/` تعمل بلا تعقيد، وCSRF يُعالَج بـ Origin check + Double Submit.

### C9 — Zod × class-validator
- **الحل:** Zod فقط. توليد OpenAPI عبر `nestjs-zod`، واستخدام نفس المخططات في الواجهة = عقد واحد.

### C10 — Prisma × Drizzle × TypeORM
- **الحل:** Drizzle. السبب: تحكم صريح في SQL والمعاملات (شرط RLS)، بلا محرك ثنائي، ووقت إقلاع أقل في حاويات صغيرة. **التنازل:** نظام بيئي أصغر وميزات إدارة أقل.

### C11 — PDF عبر المتصفح × مكتبة PDF
- **الحل:** Playwright (Chromium) لتوليد الفواتير العربية؛ تشكيل الحروف وRTL في مكتبات PDF ضعيف. **التكلفة:** 300–500MB لكل نسخة، لذا: تزامن = 2 كحد أقصى، إعادة استخدام متصفح واحد، وطابور مخصص.

### C12 — Playwright في صورة الـ API
- **الحل:** فصلها في حاوية Worker مخصصة (صورة أثقل) حتى لا تتضخم صورة الـ API.
